# 里程碑 5：艾宾浩斯遗忘曲线算法

> 范围：自定义算法工具类、复习队列查询条件、单元测试与答辩说明。  
> 不包含复习卡片 UI，不包含完整 SM-2 算法。

## 1. 标准间隔

| 记忆等级 | 间隔 | 毫秒值 | 说明 |
|---|---|---|---|
| 0 | 5 分钟 | 300000 | 新学或答错重置 |
| 1 | 30 分钟 | 1800000 | 第一次复习后 |
| 2 | 12 小时 | 43200000 | 半天后 |
| 3 | 1 天 | 86400000 | 当天巩固 |
| 4 | 2 天 | 172800000 | 第二天 |
| 5 | 4 天 | 345600000 | 第四天 |
| 6 | 7 天 | 604800000 | 一周 |
| 7 | 15 天 | 1296000000 | 两周 |
| 8 | 30 天 | 2592000000 | 最高级，长期复习 |

代码中的数组：

```kotlin
val INTERVALS_MS = longArrayOf(
    5 * MINUTE,
    30 * MINUTE,
    12 * HOUR,
    1 * DAY,
    2 * DAY,
    4 * DAY,
    7 * DAY,
    15 * DAY,
    30 * DAY,
)
```

## 2. 算法规则

```text
输入：currentLevel（0–8），correct（本次是否答对），now（当前时间戳）
输出：nextLevel、intervalMillis、nextReviewTime

步骤：
1. 把 currentLevel 夹到 0–8，防止脏数据越界
2. 如果 correct == true：
     nextLevel = min(currentLevel + 1, 8)
   否则：
     nextLevel = 0
3. intervalMillis = INTERVALS_MS[nextLevel]
4. nextReviewTime = now + intervalMillis
5. 返回结果
```

关键设计：

- **答对升级**：从当前等级升到下一级；
- **答错重置**：直接回到 0 级，5 分钟后重新复习；
- **最高级封顶**：8 级答对仍是 8 级，间隔 30 天；
- **按新等级取间隔**：例如 0 级答对后是 1 级，下一次安排在 30 分钟后；
- **时间戳统一用 Unix 毫秒**：方便和 Room 的 `next_review_time` 比较。

## 4. 复习队列查询

`Word` 实体新增两个字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `memory_level` | INTEGER | 当前艾宾浩斯等级 0–8 |
| `next_review_time` | INTEGER | 下一次复习时间戳，可为空 |

DAO 查询条件：

```sql
SELECT *
FROM words
WHERE next_review_time IS NOT NULL
  AND next_review_time <= :now
ORDER BY next_review_time ASC;
```

对应 Room：

```kotlin
@Query(
    "SELECT * FROM words " +
        "WHERE next_review_time IS NOT NULL AND next_review_time <= :now " +
        "ORDER BY next_review_time ASC"
)
fun observeDueWords(now: Long): Flow<List<Word>>
```

条件说明：

- `next_review_time IS NOT NULL`：还没排入复习计划的单词不进队列；
- `next_review_time <= now`：只取已经到期的单词；
- `ORDER BY next_review_time ASC`：最紧急的排在前面；
- `now` 是查询时传入的时间快照，时间推移后需要重新查询/刷新。

## 7. 答辩讲解话术

可以按下面这段讲，控制在 1–2 分钟：

> 我的复习算法采用简化版艾宾浩斯遗忘曲线。标准间隔是 5 分钟、30 分钟、12 小时、1 天、2 天、4 天、7 天、15 天、30 天，一共 9 个等级，编号 0 到 8。  
> 工具类只做一件事：输入当前等级、答对还是答错、当前时间，输出下一次复习时间。答对时等级加 1，最高到 8 级；答错时直接重置到 0 级。然后用新等级去间隔数组里取间隔，当前时间加上间隔，就是下一次复习时间戳。  
> 比如新词是 0 级，答对后升到 1 级，下一次安排在 30 分钟后；如果 3 级答错，回到 0 级，5 分钟后重新复习；8 级答对仍然保持 8 级，30 天后再复习。  
> 数据库里在 Word 表增加了 memory_level 和 next_review_time 两个字段。复习队列的查询条件是 next_review_time 不为空，并且小于等于当前时间，按到期时间升序排列。  
> 这个工具类是纯 Kotlin，不依赖 Android，所以可以直接用 JUnit 做单元测试。测试覆盖了标准间隔、答对升级、答错重置、最高级封顶和到期边界。

如果老师追问：

**问：为什么答错要重置到 0？**  
> 因为答错说明当前记忆不稳定，继续用长间隔会再次遗忘；先回到 5 分钟，重新建立记忆，再逐步拉长间隔。

**问：为什么按新等级取间隔？**  
> 等级表示“已经成功复习到哪一档”。0 级答对后进入 1 级，对应的下一次间隔就是 30 分钟；这样等级和间隔表一一对应，逻辑最清晰。

**问：为什么最大只到 30 天？**  
> 课程项目里 30 天已经能覆盖一个学期的复习周期；再长不利于演示和答辩，也会让队列长期没有任务。

**问：时间到了但 App 没打开怎么办？**  
> 查询使用当前时间戳和 next_review_time 比较，不依赖后台定时器；App 打开或刷新时，所有已过期单词都会进入队列。

**问：为什么不用完整 SM-2？**  
> 完整 SM-2 需要 ease factor、质量评分和多参数调整，复杂度高；本项目的目标是可解释、可测试的简化艾宾浩斯，先保证答对升级、答错重置和时间间隔正确。
