# M7.5：通知权限、WorkManager 每日复习提醒与降级方案

> 范围：Android 13+ 通知权限、NotificationChannel、RemindWorker 每日调度、首页权限关闭降级提示。  
> 不包含 P2 看板和导出功能。

## 1. 通知权限

Manifest 声明：

```xml
<uses-permission android:name="android.permission.POST_NOTIFICATIONS" />
```

Android 13（API 33）及以上在首页首次进入时：

1. 检查 `POST_NOTIFICATIONS` 是否已授权；
2. 未授权时先弹出应用自己的解释框：
   - 标题：开启复习提醒
   - 文案：每天 20:00 提醒复习；关闭通知仍会在首页显示待复习数量，但不会弹出提醒；
   - 按钮：去开启 / 暂不开启；
3. 点“去开启”后调用系统权限弹窗；
4. 用 SharedPreferences 记录已提示，避免每次进入首页都弹解释框；
5. 用户拒绝后首页显示降级提示和“去开启”按钮，直接跳到系统通知设置。

## 2. 降级方案

首页提醒条由 `ReminderViewModel` 的 `ReminderUiState` 驱动：

| 状态 | 首页表现 |
|---|---|
| 权限开启，有待复习 | 红色数字徽标 + “待复习 N 个单词” |
| 权限开启，无待复习 | 隐藏提醒条 |
| 权限关闭 | 显示“通知权限已关闭，请手动打开查看提醒” + 去开启 |

降级时：

- Worker 仍然可以运行，但 `NotificationHelper.showReviewReminder()` 检测到通知不可用会直接返回 false；
- 不抛出异常，不影响 App 使用；
- 用户仍可手动进入复习页查看待复习单词。

## 3. NotificationChannel

`NotificationHelper` 创建：

```kotlin
NotificationChannel(
    "review_reminder",
    "复习提醒",
    NotificationManager.IMPORTANCE_DEFAULT,
)
```

通知内容：

```text
标题：该复习单词了
正文：今天有 N 个单词待复习，点开继续。
```

点击通知打开 `MainActivity`。

## 4. RemindWorker

```kotlin
class RemindWorker(
    appContext: Context,
    params: WorkerParameters,
) : CoroutineWorker(appContext, params) {

    override suspend fun doWork(): Result {
        val due = AppDatabase.getInstance(applicationContext)
            .wordDao()
            .getDueWords(System.currentTimeMillis())

        if (due.isNotEmpty()) {
            NotificationHelper.showReviewReminder(applicationContext, due.size)
        }
        return Result.success()
    }
}
```

查询条件仍然是：

```sql
next_review_time IS NOT NULL
AND next_review_time <= now
```

## 5. 每日调度

`ReminderScheduler`：

```kotlin
PeriodicWorkRequestBuilder<RemindWorker>(1, TimeUnit.DAYS)
    .setInitialDelay(delayToNext20OClock, TimeUnit.MILLISECONDS)
    .addTag(WORK_NAME)
    .build()

WorkManager.getInstance(context).enqueueUniquePeriodicWork(
    WORK_NAME,
    ExistingPeriodicWorkPolicy.KEEP,
    request,
)
```

- 每天 20:00 执行；
- 如果今天 20:00 已过，自动安排到明天 20:00；
- 唯一任务名 `daily_review_reminder`；
- `ExistingPeriodicWorkPolicy.KEEP` 保证重复调用不会创建多个任务。

## 6. 防止重复调度

两层保护：

1. `ReminderViewModel` 保存 `workerScheduled` 状态，页面重复创建时直接返回；
2. WorkManager 使用 `enqueueUniquePeriodicWork + KEEP`，即使进程重启也不会重复入队。

## 7. 答辩讲解话术

> 通知提醒这块我先处理权限。Android 13 以后发通知需要 POST_NOTIFICATIONS 运行时权限，所以首页第一次进入时先弹一个解释框，告诉用户每天 20:00 会提醒复习；用户点“去开启”才触发系统权限弹窗，避免一上来就弹系统框。  
> 如果用户拒绝，我不会让功能不可用，而是降级：首页的提醒条显示“通知权限已关闭，请手动打开查看提醒”，旁边有去开启按钮；待复习数量仍然显示，用户也可以自己点复习页查看。  
> 通知通道用 NotificationChannel，重要性是 DEFAULT。真正发通知的是 RemindWorker，它每天 20:00 被 WorkManager 唤醒，查询 next_review_time 小于等于当前时间的单词，有到期单词才发通知。  
> 为了防止重复调度，ViewModel 里保存了任务状态，同时 WorkManager 用唯一任务名和 KEEP 策略，两层保证只有一个每日任务。  
> 这样即使通知权限被关闭，App 的复习队列和首页数字仍然正常，只是不弹系统通知，属于可接受的降级。

## 8. 验证方式

- 构建：`:app:assembleDebug`；
- 在 Android 13+ 模拟器首次启动，看到解释框；
- 点“暂不开启”后，首页显示降级文案；
- 授权后首页隐藏降级文案，有待复习时显示红色数字；
- 查看 WorkManager 任务：

```bash
adb shell dumpsys jobscheduler | grep com.example.wordmemory
```

- 测试通知权限：

```bash
adb shell pm grant com.example.wordmemory android.permission.POST_NOTIFICATIONS
adb shell pm revoke com.example.wordmemory android.permission.POST_NOTIFICATIONS
```
