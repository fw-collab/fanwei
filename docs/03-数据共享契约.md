# 主 App 与伴生端数据共享契约

> 适用范围：`:app`（主 App）与 `:board_app` + `:data_board_module`（伴生端）。  
> 原则：**Room 单一数据源、只读共享、最小权限、不直接暴露数据库文件。**

## 1. 方案边界

主 App 的 Room 数据库位于应用私有目录，另一个 APK 无法直接打开。本项目由主 App 在自身进程内查询 Room，再通过 `WordBoardProvider` 暴露只读 URI；伴生端使用 `ContentResolver` 查询。

```text
Room DAO（主 App 进程）
        │ 查询/聚合
        ▼
WordBoardProvider（exported=true，readPermission=signature）
        │ content://com.example.wordmemory.boardprovider/...
        ▼
ContentResolver（伴生端）
```

**不做：** 直接读数据库文件、`sharedUserId`、外部存储放置数据库、伴生端自建 Room 副本、Provider 写操作。

## 2. Provider 配置

| 项 | 值 |
|---|---|
| Provider 类 | `com.example.wordmemory.data.WordBoardProvider` |
| authority | `com.example.wordmemory.boardprovider` |
| 读权限 | `com.example.wordmemory.permission.READ_BOARD` |
| 权限级别 | `signature` |
| 导出 | `android:exported="true"` |
| 写权限 | 不声明；`insert/update/delete` 抛出 `UnsupportedOperationException` |
| 查询方式 | 固定投影 + 固定排序；忽略调用方传入的 `selection`/`sortOrder`，避免注入和越权 |

主 App 与伴生端必须使用同一签名证书。Debug 构建共用默认 debug keystore；Release 构建显式配置同一 `signingConfig`。

安装顺序建议为**先主 App、后伴生端**：`signature` 权限由主 App 定义，先装伴生端可能导致系统未识别该权限；如已先装，卸载伴生端后重装即可。

## 3. URI 与字段契约

Base URI：`content://com.example.wordmemory.boardprovider`

列名是契约的一部分：新增列只能追加，不能重命名或删除已有列；破坏性变更必须提升 `contract_version` 并同步升级伴生端。

### 3.1 `meta` — 契约版本

| 列 | 类型 | 说明 |
|---|---|---|
| `contract_version` | INTEGER | 当前为 `1` |
| `schema_version` | INTEGER | Room 数据库版本 |
| `generated_at` | INTEGER | 数据生成时间（epoch millis） |

伴生端启动时先查 `meta`；若 `contract_version` 高于自身支持版本，提示“请更新伴生端”。

### 3.2 `summary` — 今日概览

| 列 | 类型 | 说明 |
|---|---|---|
| `total_words` | INTEGER | 词库总词数 |
| `learned_words` | INTEGER | 已学词数（有过学习记录） |
| `mastered_words` | INTEGER | 已掌握词数 |
| `due_today` | INTEGER | 今日到期复习数 |
| `streak_days` | INTEGER | 连续学习天数 |
| `today_new` | INTEGER | 今日新学数 |
| `today_review` | INTEGER | 今日复习数 |
| `today_correct_rate` | REAL | 今日正确率，0.0–1.0；无作答时为 0 |

固定返回 1 行；无数据时各计数为 0，不返回空游标。

### 3.3 `daily?days=7|30` — 学习趋势

| 列 | 类型 | 说明 |
|---|---|---|
| `date` | TEXT | `yyyy-MM-dd` |
| `new_count` | INTEGER | 当日新学数 |
| `review_count` | INTEGER | 当日复习数 |
| `correct_count` | INTEGER | 当日答对数 |
| `total_count` | INTEGER | 当日作答总数 |

按日期升序返回，最多 30 行；`days` 只接受 7 或 30，其他值按 7 处理。**由 Provider 生成连续日期行**，无记录的日期补 0，伴生端不再自行补齐，保证两端看到的时间轴一致。

### 3.4 `mastery` — 掌握度分布

| 列 | 类型 | 说明 |
|---|---|---|
| `level` | TEXT | `NEW` / `LEARNING` / `MASTERED` |
| `count` | INTEGER | 该档词数 |

固定返回 3 行；无数据时三行计数均为 0。

### 3.5 `books` — 词书进度

| 列 | 类型 | 说明 |
|---|---|---|
| `book_id` | INTEGER | 词书 ID |
| `book_name` | TEXT | 词书名称 |
| `total_count` | INTEGER | 总词数 |
| `learned_count` | INTEGER | 已学数 |
| `mastered_count` | INTEGER | 已掌握数 |
| `progress` | REAL | 已学/总数，0.0–1.0 |

按 `book_id` 升序；空词书返回 0 进度。

### 3.6 `difficult?limit=10` — 难词榜

| 列 | 类型 | 说明 |
|---|---|---|
| `word_id` | INTEGER | 单词 ID |
| `word` | TEXT | 单词 |
| `book_name` | TEXT | 所属词书 |
| `wrong_count` | INTEGER | 累计答错次数 |
| `last_wrong_at` | INTEGER | 最近答错时间（epoch millis） |

按 `wrong_count` 降序、`last_wrong_at` 降序；`limit` 默认 10，最大 50。

## 4. 刷新与一致性

- 伴生端在 `onResume` 和下拉刷新时重新查询；不缓存跨页面版本。
- 主 App 完成学习/复习/测验写入后调用 `ContentResolver.notifyChange()`；伴生端可注册 `ContentObserver` 做被动刷新，也可以只做手动刷新，二者不冲突。
- 看板只读，不提供“修改目标/删除记录”等写入口，避免双写冲突。
- 主 App 被强制停止时，Provider 不可用；伴生端展示“请先打开主 App”提示，而不是反复重试。

## 5. 异常与空态约定

| 场景 | 伴生端表现 |
|---|---|
| 主 App 未安装 / authority 不存在 | 捕获 `IllegalArgumentException`，显示“未安装主 App” |
| 签名不一致 / 缺少读权限 | 捕获 `SecurityException`，显示“签名不一致，请安装同一版本” |
| 主 App 已安装但未建库 | 计数为 0，显示空数据引导 |
| 游标为空或字段缺失 | 使用默认值并记录日志，不崩溃 |
| 契约版本不兼容 | 显示“请更新伴生端/主 App” |

## 6. 验收用例

1. 主 App 写入 3 个词书、20 个单词和若干学习记录后，`summary` 与主 App 内统计一致。
2. `daily?days=7` 返回按日期升序的 7 行；`days=30` 最多 30 行；非法参数回退为 7。
3. `mastery` 三档计数之和等于总词数。
4. `difficult?limit=10` 最多 10 行，按错误次数降序。
5. 对 Provider 调用 `insert/update/delete` 必须抛出 `UnsupportedOperationException`。
6. 卸载主 App 后打开伴生端，显示“未安装主 App”，无崩溃。
7. 用不同签名安装伴生端，查询被拒绝，界面显示权限提示。
8. 主 App 新增记录后，伴生端下拉刷新能看到变化。
